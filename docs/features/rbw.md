# rbw password prompts and qutebrowser autofill

The `>bw` qutebrowser binding starts a browser-owned operation, opens this shell's
entry picker, then fills the selected login into the original form. Every entry
requires confirmation, including a single matching login. The picker always shows
the destination host. Both the entry picker and unlock prompt use the
`quickshell-private` layer namespace, matching TOTP and notifications. The form is
not submitted.

## Setup

Quickshell's prompt and pinentry helpers use Bash, jq and the standard GNU tools.
The browser/userscript implementation uses Python 3 and libpsl. This integration
supports rbw 1.15.x, Quickshell and qutebrowser's QtWebEngine backend. The rbw 1.15.0 package's signature, CLI and
configuration behavior were checked during implementation.

On this Arch/CachyOS machine, install the system package:

```sh
sudo pacman -S --needed rbw
```

The following two preferences were already configured during implementation:

```sh
rbw config set lock_timeout 900
rbw config set pinentry "$HOME/.config/quickshell/src/services/launcher/pinentry-rbw"
```

Configure the account email in your terminal, then register and synchronize:

```sh
rbw config set email 'your-account-email'
rbw register
rbw login
rbw sync
```

Default server settings use Bitwarden US. For an EU account, configure
`rbw config set base_url https://api.bitwarden.eu` before registering/logging in.
Existing server settings are preserved; check your account's region if uncertain.
Registration uses the personal API key from Bitwarden's account settings. Enter
API secrets and the master password only in the masked prompt, not in shell
arguments or chat. rbw's supported two-factor methods apply.

Restart Quickshell once after first installing this integration, then run
`:config-source` in qutebrowser. A running shell can retain old QML enum metadata:
adding the `Secret` mode may require a full process restart, even after a hard
reload. In that state the prompt previously stayed invisible; unsupported secret
modes now fail immediately with a fixed restart diagnostic in the shell log.

```sh
qs kill -p "$HOME/.config/quickshell"
qs -d -n -p "$HOME/.config/quickshell"
```

Focus the username or password input of a supported login form and
press `>bw`. Direct commands also support:

```text
:rbw-fill
:rbw-fill username
:rbw-fill password
:rbw-fill totp
```

Single-field modes fill the field focused when the operation starts. TOTP is
generated by rbw and filled directly. There is no automatic clipboard copying.

`RBW_PROFILE` selects the rbw profile; setup commands and the browser must use the
same profile. The configured pinentry and timeout belong to that profile and can
affect other applications using its agent.

## Secret-input API

`src/services/launcher/launcher.sh --secret --prompt "Master Password"` opens a
field that is masked by default. Enter confirms and Escape cancels; there are no
Unlock or Cancel buttons. Its eye button
toggles visibility so you can check your typing; closing or accepting resets the
field to masked and clears it. Secret prompts use a separate window in the
`quickshell-private` layer namespace, matching TOTP and notifications. Optional `--description` and
`--error` provide public prompt metadata. Success writes only the exact UTF-8
value to stdout, without appending a newline; cancellation exits 1 and errors or
timeouts exit 2. Secret values must never be passed in arguments.

`secret_prompt.sh` reads bounded JSON replies through a private FIFO and streams
the decoded value through jq; secrets never enter jq arguments or shell command
substitution. Exact UTF-8 output, including trailing newlines, is preserved.

`pinentry-rbw` implements the pinentry subset used by rbw, including percent
escaping, error prompts and cancellation. It transfers the accepted value to
rbw over stdout. An interrupted client cancels its panel; a watchdog handles
abrupt client death and removes abandoned request metadata. The default timeout
is five minutes. No password enters the normal picker query or remembered choice.

## Browser operation and exposure controls

The qutebrowser configuration registers `rbw-fill` and `rbw-fill-once` through
`src/patches.py`. Browser implementation lives in `src/rbw.py` and `src/rbw_form.js`;
the executable helper is `~/.local/share/qutebrowser/userscripts/qute-rbw`, with
backend code in `lib/rbw_client.py` in that repository.

The browser captures the actual tab and document before the UI opens. Closing,
navigating or switching away from the tab cancels the operation, including a
same-URL reload. New operations and configuration reload revoke previous work.
The initial request expires after five minutes; the helper offers ready
credentials for at most 30 seconds, and browser socket I/O is limited to ten
seconds with a maximum 64 KiB payload.

The command FIFO carries an opaque handle only. A handle in logs/macros/repeat
state cannot recreate an operation. Only a pending operation in the originating
window can claim it, and the first valid claim consumes it even if filling fails.
Credentials travel through a user-private Unix socket with ownership, mode and
Linux peer-process checks. Only requested fields reach the browser. Runtime
directories contain sockets/FIFOs and public prompt/entry metadata, never saved
credential payloads.

Filling uses a fixed script in a dedicated isolated JavaScript world through the
browser API. Credentials never enter `fake-key` or `jseval` commands. The script
returns static status codes, dispatches input/change events and does not submit.
Raw subprocess errors, JSON errors, JavaScript source, field contents and
exceptions are not forwarded to browser logs or notifications. Normal debug
logging remains available.

The rbw helper suppresses inherited debug logging for its invocations and newly
started agents. A separately started agent has its own logging environment; stop
an agent started with verbose logging before using this integration. Existing
logs are not retroactively scrubbed.

## Supported forms and matching limits

`rbw: focus a supported login field and try again.` means the captured field
could not be used. `rbw: entry picker unavailable; check Quickshell.` indicates a
launcher startup or response failure. Failed IPC/JSON commands return exit 2;
exit 1 is reserved for a cancelled picker. Raw launcher diagnostics remain
suppressed. Check launcher availability without accessing the vault:

```sh
qs ipc -p "$HOME/.config/quickshell" call launcher alive
```

- Full login requires an unambiguous visible username/email input and one password
  input in the same form. Focus one of those fields before opening the picker.
- Username/password/TOTP-only modes support an appropriate focused top-level input.
  Ambiguous forms, unsupported inputs, frames and shadow-DOM inputs are refused.
- The intended document, field types and visibility are checked again before
  filling. Values that HTML inputs would normalize are refused. Line breaks/NUL
  in login credentials are unsupported; leading/trailing password spaces are
  preserved.
- Metadata URLs produce suggestions only. The selected entry's complete URI
  rules authorize filling. Domain/host, exact, prefix and Never rules are checked;
  prefixes additionally require the same origin. Public-suffix host expansion is
  rejected using libpsl. Regex rules are intentionally unsupported and cannot
  authorize a fill. There is no broad-name or whole-vault fallback.
- rbw's public credential JSON omits the master-password-reprompt flag. The helper
  checks that flag in the encrypted local cache before and after retrieval.
  Protected entries and missing/unknown metadata are refused rather than bypassing
  their policy. This cache schema is version-sensitive; unsupported rbw versions
  are refused. The check reads policy and does not decrypt the cache.

These controls cover this integration's transport, persistence and diagnostics.
The destination website receives the login password and can itself log it,
including in console messages. Same-user/root compromise, memory inspection,
swap and core dumps are outside the guarantee. QML/Bash/Python strings are cleared
when finished but cannot promise secure zeroization. The `quickshell-private`
namespace follows the existing switchable compositor capture rule used by TOTP
and notifications; masking or revealing does not itself control screen capture.

## Checks

All new tests for all three repositories live here:

```sh
bash tests/security/rbw/run.sh
bash tests/launcher/launcher.sh
bash tests/qml/lint.sh
# Optional: briefly display the synthetic masked panel on Wayland.
bash tests/security/rbw/native.sh
```

All test runners and mocks are Bash; QML fixtures exercise Quickshell. The suite
uses jq and socat, synthetic credentials, mocked rbw, loopback HTML in the real
qutebrowser/QtWebEngine and an isolated offscreen Quickshell. It checks filling, direct single-field
modes, diagnostic privacy, replay/expiry, peer identity, endpoint permissions,
malformed/oversized responses, navigation, pinentry, cancellation and cleanup.
It never logs into or writes to a real vault and does not monitor the desktop
clipboard. The optional real CLI smoke check uses a separate synthetic profile;
set `RBW_TEST_EXECUTABLE` to a verified rbw executable when it is not on PATH.

The test runner may need execution outside a restrictive sandbox to permit Unix
peer checks and Qt/Quickshell IPC. Disposable profiles and artifacts stay in
private temporary directories. Other repository locations can be selected with
`QUTE_RBW_SCRIPTS_ROOT` and `QUTE_RBW_BROWSER_ROOT`.

Vault management (add/edit/generate/delete) is a later implementation stage.
